交付范围

本次可运行的数据路径是现有 FastAPI＋SQLite 的完整本地多用户方案。同一账套的成员连接同一个后端服务，由服务端控制权限与事务。支持本机不同账号切换，也可由同一受控后端提供局域网访问。

外部同步与核对飞书／Google 官方 API 连接、字段映射、加密凭据、02:17 定时与立即同步、来源基线锁定、改行／缺行／重复 ID 预警、三单分配与审计对比。
科目与余额表4/6/8/10 位科目、自定义下级、名称与启停、客户／供应商／部门／研发项目／银行账户辅助核算、逐级余额树、联查和 CSV 导出。新增业务税额使用进项／销项明细；历史父级发生额保留。
多角色权限按账套授予财务总监、会计、出纳、仓管／填报员；接口、列表、详情、导出、附件、待办与页面入口统一校验。默认要求登录，未创建首位总监时不开放业务接口。
首页常用模块压缩顶部区域，七大模块及子功能可勾选／取消、拖拽或上移下移排序；按账号和账套保存，失权项过滤。
待办与流程中心顶栏数量角标与浮窗；我的待办／待阅／已办／已阅／发起；分类、发起人、状态筛选；报销会计初审＋总监终审，凭证、更正、红冲、异常、催票接入。
税务结转按月预览净销项、可抵扣进项、上期留抵与差额；生成唯一结转草稿，独立终审后过账；零／留抵不造零金额凭证；重复生成复用、来源变化拦截、跨期留抵承接。
账期与迁移锁定／解锁独立审批，检查未过账凭证、同步异常和税务状态；保存结账快照。增量升级旧 SQLite，保留凭证 ID、原始分录和历史台账。

启动与首次配置

  1. 关闭旧版服务后，运行项目根目录的 启动简账.bat，打开 http://127.0.0.1:8000/app。脚本安装新增依赖，服务启动时自动执行增量迁移。
  2. 若尚未启用权限，页面要求创建首位财务总监；填写自己的账号和至少 10 位密码。已有账号继续使用原密码，账套数据不重新导入。
  3. 总监进入“总账模块 → 协作成员与权限”，创建会计、出纳、填报员，分别指定账套角色和填报范围。旧管理员映射为总监、旧制单人映射会计；旧复核人暂保留只读，由总监明确授予终审权限。
  4. 在协作设置确认账套纳税人类型。一般纳税人使用进销项结转；小规模纳税人不套用进项抵扣模型。
  5. 在“科目与辅助核算”补充部门、研发项目、供应商等对象。新增科目立即出现在凭证与余额表；已使用科目保留历史，采用停用管理。

财务审批要求独立人员。一个账号可兼任多角色，仍不能终审本人制单或发起的申请。测试时可在演示账套使用两个独立账号；正式账套不提供任意切换身份的快捷按钮。

表格连接与定时同步

  1. 总监打开“业务核算 → 外部表格与同步”，新增飞书或 Google 连接，填写表格 Token／ID、完整表或工作表及字段映射。
  2. 点“配置凭据”：飞书填 App ID／App Secret，Google 填官方服务账号 JSON，并将表格共享给服务账号。凭据只写入服务端加密存储，页面不会读回密钥。
  3. 至少映射业务日期和含税金额；常用字段包括单据号、类型、行号、数量、税额、款项性质、票是否开齐、是否催票和研发项目。辅助对象可填系统中已配置的业务编码或不重名的名称。
  4. Google 表须有稳定、唯一且受保护的 external_id 列；飞书用官方 record_id。填报人归属只认官方可验证的创建者标识，无法验证归属的外部记录只向财务开放。
  5. 先点“立即同步”，查看新增／成功／异常和来源错误；核对正确后开启每日同步。默认北京时间 02:17，本地模式依赖服务运行；启动后会补跑当日任务，完整读取可补入停机期间的新增行。

本地首版单连接最多 20,000 行，采用完整读取核验。旧行修改只生成证据，不覆盖入账基线；空表或分页失败不判断删除，缺失需后续独立完整扫描确认。外部“仅追加”还需在飞书／Google 设置保护或受控提交入口。相同证据的异常去重；处理后不按天重复派发，证据变化生成新异常。

金额按分精确保存；数量最多六位小数。三单支持分批到货、分次开票的数量和金额分配，并检查单位金额和税额。预付款不会因天然未到货／未开票直接当作篡改。

日常操作链路

  • 仓管／填报员：授权模块新增本人登记 → 提交；报销由会计初审、总监终审。
  • 会计：核对锁定台账 → 提交业务审批 → 从批准台账生成凭证草稿 → “凭证审批与过账”提交 → 总监在流程中心终审 → 会计过账。
  • 锁定记录更正：保留原版本，创建有原因的更正草稿；已过账先申请红冲，再在开放期间创建更正版本。原始金额和来源快照始终保留。
  • 出纳：现金／银行收付款登记、授权关联台账查看、追加催票／收票事件。收票完成可结束催票待办；无总账凭证修改权限。
  • 历史未审核凭证若没有制单身份，不猜填人员；总监经核实后可使用 POST /api/v2/vouchers/{id}/attest-owner，提供真实制单账号、原因和版本，再提交独立终审。

税务结转与账期

“税务管理与导航 → 进项与销项期末结转”：选择月份 → 测算 → 生成结转草稿／留抵确认单 → 提交终审 → 过账。净销项减去可抵扣进项和上期留抵，大于零生成借“转出未交增值税”、贷“未交增值税”的草稿；小于等于零记录留抵或零。待认证转入只计一次，进项转出调减可抵扣额，红字按原符号参与。

历史直接记在 2221／222101 的税额不能自动猜拆；已缴、预缴、减免、退税等特殊事项进入人工核对。首次启用的期初留抵须以真实底稿填写，后续月份承接上月已确认结果。结转后基础变化会拦截旧结果过账，已过账更正走红冲。账期锁定／解锁在“总账模块 → 账期锁定与解锁”发起，由独立总监终审。

部署与配置边界

.env 已开启强制登录。数据库、附件、加密凭据、CORS、调度开关、主机和端口通过配置抽离，参考 .env.example。新增 Dockerfile 支持标准容器部署；数据库、附件与密钥需挂载持久化目录。免费容器的临时文件系统只适合验证，正式账务需要可靠持久化。

静态发布已包含 assets/，可运行 python scripts/package-static.py 输出仅含网页资源的 dist/。数据库、附件、.env、私有凭据和升级备份不会加入静态包。

Serverless 状态：项目已有 Supabase Schema／RLS、Pages 和 Actions 初稿继续保留。本次完成的是本地完整多用户路径及配置拆分；尚未交付把现有全部 Python 命令迁移为 Supabase RPC／Edge Functions 的云端运行适配，也没有部署外部云项目。不能仅发布静态网页就获得跨设备共享账务。若实施纯 Serverless 路径，仍需独立完成该适配、数据迁移及云端验收。

外部连接状态：未提供真实飞书／Google 凭据，因此官方接口适配代码已实现，同步业务规则用隔离来源数据验证；尚未针对你的真实表格执行联调或导入。
